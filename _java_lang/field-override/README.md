# 필드 접근과 메서드 접근 예제

`XyzTest`는 상위 클래스의 공통 `process()`가 하위 클래스별 `foo`, `bar` 값을
어떻게 읽을 수 있는지 확인하는 예제예요. 같은 이름의 필드를 직접 참조할 때와
메서드로 접근할 때의 차이를 비교하고, 상위 필드를 직접 초기화하거나 실행 중에
변경하는 대안도 살펴봐요.

## 확인 순서

`AbcWorker.process()`는 값을 출력하고 `walk()`를 호출하는 공통 흐름을 제공해요.
`XWorker`와 `YWorker`는 서로 다른 값과 `walk()` 구현을 제공하며, 다음 예제는
`main()`에서 호출되는 순서대로 실행돼요.

1. `P1`: 상위 클래스와 하위 클래스가 같은 이름의 필드를 각각 선언해요. 상위
   `process()`가 `this.foo`, `this.bar`로 접근하면 하위 객체에서도 상위 필드인
   `Abc_Foo`, `Abc_Bar`를 읽어요. 필드는 메서드처럼 오버라이딩되지 않고
   선언된 클래스에 따라 결정된다는 점을 확인해요.
2. `P1R1`: 상위 `process()`가 `this.foo()`, `this.bar()` 메서드를 호출해요.
   메서드는 실제 객체의 구현으로 동적 디스패치되므로 `XWorker`에서는 `X_Foo`,
   `X_Bar`를, `YWorker`에서는 `Y_Foo`, `Y_Bar`를 읽어요.
3. `P1R3`: 하위 클래스에 같은 이름의 필드를 만들지 않고 생성자에서 상위 필드를
   초기화해요. 상태를 한 곳에만 두면 상위 `process()`가 필드에 직접 접근해도
   하위 클래스별 값을 읽을 수 있음을 확인해요.
4. `P1R2`: 하위 필드와 상위 필드를 모두 유지하고, `walk()`에서 하위 값을 상위
   필드로 복사해요. 가상 스레드에서 `process()` 전후 값을 출력해 복사 이전에는
   상위 기본값을, 이후에는 하위 값을 읽는 것을 확인해요.

   값을 복사한 뒤 `XWorker`는 1000ms, `YWorker`는 100ms 동안 대기하므로 두 번째
   상태 로그는 대체로 `YWorker`가 먼저, `XWorker`가 나중에 출력돼요. 최초
   상태와 `walk()` 로그의 순서는 스레드 스케줄링에 따라 달라질 수 있고,
   `Thread.sleep()`도 엄밀한 실행 순서를 보장하지는 않아요.

5. `P1R4`: `P1R2`처럼 실행 중 상위 필드를 변경하되, `XWorker` 값에 인스턴스
   식별 정보를 붙여 각 스레드가 생성한 객체의 상태가 서로 구분되는지 확인해요.

   `XWorker`는 0~999ms 중 무작위 시간 동안 대기하고 `YWorker`는 100ms 동안
   대기해요. 따라서 `XWorker`의 대기 시간이 짧으면 `XWorker`가, 길면
   `YWorker`가 두 번째 상태 로그를 먼저 출력하는 경향이 있어 실행할 때마다
   완료 순서가 달라질 수 있어요. 여기서도 실제 순서는 스레드 스케줄링의 영향을
   받으므로 대기 시간만으로 보장되지 않아요.

## 비교 요약

| 단계 | `process()`의 값 접근 | 상태 구성 또는 변경 | 주요 관찰 결과 | 실행과 대기 시간 |
| --- | --- | --- | --- | --- |
| `P1` | 필드 직접 접근 | 상위·하위 클래스에 같은 이름의 필드 선언 | 상위 필드의 `Abc_Foo`, `Abc_Bar`를 읽음 | |
| `P1R1` | 메서드 호출 | 상위·하위 클래스의 접근 메서드가 각 필드를 반환 | 동적 디스패치로 하위 클래스별 값을 읽음 | |
| `P1R3` | 필드 직접 접근 | 생성자에서 하나뿐인 상위 필드를 초기화 | 상위 필드에서 하위 클래스별 값을 읽음 | |
| `P1R2` | 필드 직접 접근 | `walk()`에서 하위 필드를 상위 필드로 복사 | 최초 로그 순서는 유동적이고 두 번째 로그는 대체로 `YWorker` 다음 `XWorker` | 가상 스레드, `XWorker` 1000ms·`YWorker` 100ms |
| `P1R4` | 필드 직접 접근 | `walk()`에서 객체 식별 정보를 포함해 상위 필드 변경 | 두 번째 로그의 완료 순서가 실행마다 달라질 수 있음 | 가상 스레드, `XWorker` 0~999ms·`YWorker` 100ms |

JDK 21이 필요하며 별도 Maven 설치 없이 Maven Wrapper로 빌드할 수 있어요.
아래 명령은 `_java_lang/field-override/`에서 실행해요.

## 빌드

```sh
./_build.sh
```

Maven Wrapper를 직접 실행해도 돼요.

```sh
./mvnw clean package
```

Windows에서는 `mvnw.cmd clean package`를 사용해요. 실행에 필요한 로깅
의존성은 `target/dependency/`에 복사돼요.

## 실행

일반 실행은 Maven을 거치지 않는 스크립트를 사용해요.

```sh
./_run.sh XyzTest
```

인수 없이 실행하면 사용법을 출력해요. Exec Maven Plugin의 기본 실행 클래스도
`XyzTest`로 설정되어 있어요.

```sh
./mvnw exec:java
```
